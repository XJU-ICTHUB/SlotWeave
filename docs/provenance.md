# 实现结构与接口约定

算法推导见 [算法说明](solution.md)，模块入口和状态变量见 [代码导读](code-guide.md)。本页说明接口、文件组织和运行约定。

## 在线接口

求解器通过 [solution.h](../include/solution.h) 中的四个函数与调用方交互：

```cpp
void init(int N, const std::vector<std::pair<int, int>>& services);
void apply_add(int id, int count);
void apply_remove(int id, int count);
const std::vector<int>& grid();
```

- 圆环长度不超过10,000，在线操作数不超过1,000。格子下标为 `0..N-1`，0表示空位。
- 外部服务ID映射为紧凑的内部类型槽位；ID、类型槽位和格子下标分别维护。
- 增删操作先确定实际修改数量，再优化布局。删除数量夹到该服务现有数量，增加数量防御式夹到空位数量。
- `grid()` 返回当前公开网格的常量引用。调用方负责输入输出；求解器不定义 `main()`。
- `init()` 重置网格、索引、操作记账和伪随机流，使同一进程可以依次处理多个测试。

## 单翻译单元与模块顺序

[src/solution.cpp](../src/solution.cpp) 按固定顺序包含18个实现片段。主要依赖依次为配置、状态与代价、局部搜索、强制安放、分层重建、操作流水线、初始化和公开入口。

`.inc` 是阅读与维护的边界，不能分别编译。包含顺序同时维护声明可见性、匿名命名空间、内联和宏生命周期；普通引擎与极小规模引擎分别清理配置，避免互相影响。

需要单文件时，运行 `python3 tools/amalgamate.py --out build/Solution.cpp`。生成文件与模块实现使用相同的四函数接口。

## 状态与目标约定

服务与空位都参与环形间隔评价。普通引擎维护同类前后继、类型位图、空位索引和代价缓存；所有写入与交换必须同步更新这些结构。

稳定性相对本次操作入口记账：一个格子反复写入后，只看最终值是否与入口值不同。时间戳区分当前操作的原值记录，恢复原值能够返还改动成本。引擎维护当前布局和少量在线汇总计数。

均匀度使用整数gap代价和定点权重。局搜、重建与后处理共享改动计费模型，但候选窗口、前瞻和工作预算各有适用范围。固定伪随机流负责候选生成，有限候选搜索和有预算的分支定界均属于启发式方法。

## 算术与工具边界

求解内核使用加减、比较、位运算和移位；乘除由软件辅助函数实现。位查询、增量索引、缓存和固定宽度展开用于降低运行开销。

本地运行器和验证器单独负责输入输出、浮点评分、计时与诊断。`quality` 为 `0.55×mean(U)+0.35×mean(V)`；速度项需要额外的参考耗时，不能由这个本地质量值推得。

## 验证与修改

数量守恒、接口契约、独立评分、完整轨迹和运行成本分别验证，具体结果见 [验证记录](results.md)。有限输入上的一致性不能证明任意输入等价。

调整候选顺序、平局规则、预算、前瞻或阶段顺序后，应重新检查完整操作轨迹和实际耗时。只改变网格数组而未维护索引，或只按交换次数估算改动成本，都会破坏后续搜索的前提。
